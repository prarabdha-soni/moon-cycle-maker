## Architecture

**Petal** is a mobile-first menstrual/pregnancy cycle tracker (Clue/Flo-inspired). It is a fully client-side SPA — there is no backend. All user state lives in `localStorage`.

### Routing

File-based routing via **TanStack Router**. Routes live in `src/routes/`. The file `src/routeTree.gen.ts` is auto-generated by the Vite plugin — never edit it manually. The router is created in `src/router.tsx` and mounted in `src/main.tsx` with a shared `QueryClient` injected through router context.

### Three tracking modes

The app has three mutually exclusive modes stored in `localStorage` as `petal:mode`:

| Mode       | Home route  | Description                               |
| ---------- | ----------- | ----------------------------------------- |
| `regular`  | `/`         | Period, mood, symptoms — CycleRing view   |
| `conceive` | `/conceive` | Fertility-first: BBT, CM, ovulation tests |
| `pregnant` | `/pregnant` | Week-by-week pregnancy tracker            |

The root index route (`/`) reads `petal:mode` synchronously on mount and immediately `navigate({ replace: true })` to the correct home for the current mode. The `ModeSwitcherPill` component handles switching modes and redirecting.

### Onboarding flow

Gated by `petal:onboarded` in localStorage. If unset, the user is redirected to `/welcome-mode`.

```
/welcome-mode
  ├── conceive → sets petal:onboarded → /conceive
  ├── pregnant → /welcome-last-period → /pregnant
  └── regular  → /welcome-supplements → /welcome → /
```

### localStorage keys

All app state uses the `petal:` namespace:

- `petal:onboarded` — any truthy string; presence means onboarding complete
- `petal:mode` — `"regular"` | `"conceive"` | `"pregnant"`
- `petal:lastPeriod` — ISO date string (LMP — last menstrual period)
- `petal:cycleLength` — integer string (days)
- `petal:name` — user display name
- `petal:profile` — serialized profile object (full record)

### AppShell

Every main screen is wrapped in `<AppShell>` (`src/components/AppShell.tsx`), which renders:

- A fixed header with title, optional back button, optional `rightSlot`/`leftSlot`, and `ProfileIcon`
- A `<main>` with `pb-32` to clear the bottom nav
- A fixed `<BottomNav>` with 5 tabs: Cycle (mode-aware route), Med, Calendar, Analysis, Product

### Design tokens

Defined in `src/styles.css` using Tailwind v4 `@theme inline`. Key semantic color tokens:

| Token                       | Color            | Usage                                     |
| --------------------------- | ---------------- | ----------------------------------------- |
| `period` / `period-light`   | Deep red / coral | Menstruation segments                     |
| `fertile` / `fertile-light` | Teal blue        | Fertile window, primary interactive color |
| `ovulation`                 | Green            | Ovulation marker, Conceive mode accent    |
| `pms`                       | Amber            | PMS indicator, Pregnant mode accent       |
| `track`                     | Neutral gray     | CycleRing background track                |

Fonts: `font-display` → Fraunces (serif, for headings/titles); `font-sans` → Inter (body text).

### Component conventions

- `cn()` from `src/lib/utils.ts` is used for all conditional class merging (clsx + tailwind-merge)
- UI primitives live in `src/components/ui/` — these are shadcn/ui components wrapping Radix UI; do not modify them directly, regenerate via shadcn CLI if updates are needed
- App-specific components go in `src/components/` (AppShell, BottomNav, CycleRing, ModeSwitcherPill, ProfileIcon)
- Route components define their own `head()` metadata (title + OG tags) inline via TanStack Router's `head` option
